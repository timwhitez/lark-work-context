## 后续改进候选

以下是下一轮可验证的方向，不是本轮已经发现的缺陷，也未因此扩充 SKILL.md：

1. 若真实任务仍把无时间戳证据当作实时状态，收紧 Apply context 中的时效句，明确仅在“当前状态”缺口影响结论时定点复核。
2. 若模型反复读取同一份官方说明，合并 Gather evidence 第 1、2 步中的复用要求，减少重复加载提示；不增加命令手册。
3. 若模型因完整汇总而无限读取历史，微调 Gather evidence 第 5 步，进一步区分目标范围覆盖与穷尽全部来源；继续保持按证据停止，不设固定轮数。
4. 若输出经常堆砌不相关的限制，压缩最后的交付规则，只保留会改变当前结论或后续动作的限制。

下一轮应使用带工具结果的多步任务、较长对话及不同模型，观察实际选源、补读和停止行为；单次固定材料判断不足以证明稳定收益。

## 脚本与成本

不增加运行时脚本。本轮没有发现需要固定程序处理的重复确定性操作；查询、来源冲突与证据充分性仍由模型判断，CLI 契约由官方技能维护。仓库中的 check.mjs 只负责维护时的结构检查。

没有测量 token、时延或实际业务工具调用成本，也未进行统计显著性检验。技能组输出更详细，但不能仅凭输出长度推断 token 成本或成本收益。
